## Why Task 5a previously never ran

The 2026-07-24 handoff attributed the stall to a Docker registry/BuildKit
timeout. That was a symptom. Six distinct blockers were found this session, each
hidden behind the previous one, each confirmed with a controlled test rather
than inferred:

1. **`--config-file false` is rejected by Cypress 13.** Removed in Cypress 10+.
   The wrapper would have failed at launch on every run. A config file outside
   the project also fails, because Cypress resolves `typescript` relative to the
   config's directory.
2. **`internal: true` makes published ports unreachable.** Verified with an A/B
   control: an ordinary bridge network served `127.0.0.1:<port>`, an internal one
   did not. Cypress could never have reached the app or the fixture. The
   `com.docker.network.bridge.enable_ip_masquerade=false` alternative does not
   block egress on Docker Desktop for Mac, so it is not a substitute.
3. **BuildKit was wedged on this machine.** `docker build` and `docker buildx ls`
   hung indefinitely while `docker ps` and `docker compose config` responded
   instantly.
4. **The macOS login keychain is locked to non-interactive sessions.** Compose
   resolves registry credentials for every service before building and fails with
   `keychain cannot be accessed because the current session does not allow user
   interaction`. Pointing `DOCKER_CONFIG` at an empty directory does **not** avoid
   it. Direct `docker build` with the classic builder is unaffected.
5. **The sign-up entry point was sampled once with no retry**, racing
   `/api/config`. The onboarding overlay renders only after that fetch resolves,
   and the sign-up toggle is hidden while onboarding is active, so the spec
   consistently chose the wrong branch.
6. **The changelog modal covers `#chat-input`.** `(app)/+layout.svelte:330` shows
   it to admins whose stored settings version differs from the running one, and
   `beforeEach` clears storage, so it reappeared every test.

Root cause behind 3: a `docker buildx ls` process from the 2026-07-24 session had
been hung for **14 hours**, together with its parent shell and another stale
process. All three were killed this session.

## Two findings that were product behaviour, not bugs

Both invalidated assumptions baked into the Task 5a brief and spec:

- `backend/open_webui/routers/auths.py:844` permanently sets
  `ui.enable_signup = False` once the first account is created and promoted to
  admin. That persisted value overrides `ENABLE_SIGNUP=true`. **The sign-up UI can
  be exercised exactly once per isolated stack**, so the spec's per-test
  disposable account is impossible by design.
- `MessageInput.svelte:680` gates the web-search control on
  `$_user.role === 'admin'` or an explicit permission. Only the first account is
  admin. Reusing that single account is therefore required for the confirmation
  case, not merely convenient.

The spec now creates one disposable account in `before()` and signs in through
the normal UI in each test.

## One real product bug, fixed

`src/lib/components/OnBoarding.svelte` — **pre-existing, unchanged versus
`origin/main`**, unrelated to the companion feature, surfaced by the new smoke
test.

When autoplay is blocked, `playBackgroundVideo()` registers document-level
`click`/`touchstart` listeners that close over `videoElement`. Dismissing
onboarding destroys the `<video>`, so `bind:this` nulls the binding — and the
very click that dismissed it then fires the handler, producing
`Cannot read properties of null (reading 'play')`. Cypress fails the test on any
uncaught application error.

Fixed with a one-line optional-chaining guard plus an explanatory comment. The
alternative — a `Cypress.on('uncaught:exception')` suppression — was rejected
because it would hide a genuine user-facing error to make a test pass.

**This must be a separate commit from the test coverage.** It is product code in
an otherwise test-only task.

## Deviations from the Task 5a brief — all require review

The brief's file list is not achievable as written, because it assumes Docker can
publish a port from an `internal` network. It cannot.

1. **`cypress.config.ts` (new, tracked).** Cypress 10+ requires a project config
   file, and it must live in the project directory for ts-node's local
   `typescript` resolution. It deliberately declares **no `baseUrl`**, so a bare
   `cypress run` cannot reach a live, user-managed, or production stack. The
   isolated origin is still injected only by the wrapper. A runner test asserts
   the absent `baseUrl`.
2. **`deploy/tide-stack/cypress-loopback-gateway/` (new).** A fixed, credential-
   free TCP forwarder — the only member of both the internal network and a second
   publishable one. `fake-openai` and `tide-bot` keep zero egress and publish no
   ports of their own. Verified live: the fixture status route was reachable on
   the generated loopback port **and** egress from `fake-openai` was `BLOCKED`.
   The forwarder reads no environment, mounts no host path, and hard-codes its two
   upstreams; runner tests assert all three.
3. **Compose builds replaced by direct builds.** The wrapper now builds each
   fixture image with `docker build` (labelled with the project name) and runs
   `compose up --no-build`, so Compose never reaches the credential path.
   `DOCKER_BUILDKIT=0` is set in the wrapper's own clean environment; it is
   wrapper-owned and never caller-supplied.
4. **Fixture images are removed explicitly at teardown.** `down` only removes
   images Compose itself built. This also fixes a real leak in the original
   design: two orphaned fixture images from the 2026-07-24 run were still on this
   machine and were removed this session.
5. **A timeout on the Cypress spawn**, so a wedged browser cannot strand the
   isolated project and skip the unconditional teardown.
6. **The `OnBoarding.svelte` product fix** described above.
